**цель**: Оптимизация разработки при помощи архитектурных паттернов разработки.

**Model, View, Controller (MVC)** — это шаблон (паттерн) программирования, разделяющий архитектуру приложения на три модуля: модель (Model), представление (View), контроллер (Controller). Простыми словами, он позволяет изменять каждый компонент независимо друг от друга для простой разработки и поддержки веб-приложений.

1. Задание 1.

Создаем index.php
   
```php
<?php 

declare(strict_types=1); 

$uri = parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH); 

$uri = rtrim($uri, '/') ?: '/'; 

echo "<pre>"; 

echo "REQUEST_URI: {$_SERVER['REQUEST_URI']}\n"; 
echo "PATH:        {$uri}\n"; 
echo "METHOD:      {$_SERVER['REQUEST_METHOD']}\n"; 
echo "</pre>"; 

switch ($uri) { 

    case '/': 

        echo "<h1>Главная страница — список статей</h1>"; 

        break; 

    case '/about': 

        echo "<h1>О проекте</h1>"; 

        break; 

    default: 

        if (preg_match('#^/article/(\d+)$#', $uri, $m)) { 

            echo "<h1>Статья №{$m[1]}</h1>"; 

        } else { 

            http_response_code(404); 

            echo "<h1>404 — страница не найдена</h1>"; 

        } 

}
```

Здесь реализована простая маршрутизация вручную. Если мы перейдем на / или /about то окажемся на этих страницах, в иных случаях сработает кейс default и проверка на наличие /article в запросе, если его нет то выводим ошибку 404 и сообщаем что страницы не существует. При наличии открываем нужную статью.

При росте сайта, новых страниц и соответственно новых маршрутов этот код будет расти всё больше и становится всё менее читаемым и оптимизированным. Чтобы решить эту проблему реализуем **роутер**


2.  Задание 2.
   
   **Роутер (Router, маршрутизатор)** в архитектуре MVC — это компонент, который принимает входящий HTTP-запрос (URL) и определяет, какому контроллеру и какому методу (действию) этого контроллера его передать. 
   

##### Создаем Router.php:
   
   
   ```php
<?php 

namespace App\Core; 

class Router 

{ 

    private array $routes = []; 

    public function get(string $path, callable|array $handler): void 

    { 

        $this->routes['GET'][$path] = $handler; 

    } 

    public function post(string $path, callable|array $handler): void 

    { 

        $this->routes['POST'][$path] = $handler; 

    } 

    public function dispatch(string $method, string $uri): void 

    { 

        $uri = parse_url($uri, PHP_URL_PATH); 

        $uri = rtrim($uri, '/') ?: '/'; 

        foreach ($this->routes[$method] ?? [] as $route => $handler) { 

            $pattern = '#^' . preg_replace('#\{(\w+)\}#', '(\d+)', $route) . '$#'; 

            if (preg_match($pattern, $uri, $matches)) { 

                array_shift($matches); 

                if (is_array($handler)) { 

                    [$class, $action] = $handler; 

                    (new $class())->$action(...$matches); 

                } else { 

                    $handler(...$matches); 

                } 

                return; 

            } 

        } 

        http_response_code(404); 

        echo '404 Not Found'; 

    } 

}
   ```

Итак, стока многа сложных букав что здесь вообще происходит, разбираем.

Это наш роутер/маршрутизатор, у нас есть два метода класса get и post. Эти методы записывают(регистрируют) маршруты в массив, а именно шаблон запроса, его метод и обработчик. 
В качестве обработчика в будущем у нас будет для этого класс. 
Зачем всё это? 

А это и есть та альтернатива нашему ручному маршрутизатору, вместо того чтобы создавать десятки маршрутов и обработку каждого из них, мы просто добавляем их в массив и обрабатываем одним маршрутизатором. 
Теперь когда пользователь вводит запрос, запрос обрабатывается методом dispatch, тут тоже происходит много всякого, но если просто то запрос очищается от лишних символов, и ищется маршрут в массиве routers. Если маршрут найден вызываем метод нашего обработчика, который уже знает что делать. Если маршрута нет то сообщаем об ошибке 404.

```php
<?php

spl_autoload_register(function (string $class) {

use App\Core\Router;

$router->dispatch($_SERVER['REQUEST_METHOD'], $_SERVER['REQUEST_URI']);
```


Ну теперь когда у нас есть такой хороший роутер мы убираем из index.php ручную маршрутизацию и скидываем всю обработку на роутер. Просто регистрируем маршруты, и обработчики. Но обработчики мы еще не сделали поэтому просто сделаем вызов функции print с текстом чтоб просто убедится что всё работает.

Краткий вывод: В ходе этой работы мы создали основную страницу и реализовали роутер, теперь наш сайт уже умеет обрабатывать запросы и выполнять нужное действие. Этот этап важен для разработки MVC т.к нам нужно знать к какому контроллеру обращаться когда пользователь отправляет какой-либо запрос.
