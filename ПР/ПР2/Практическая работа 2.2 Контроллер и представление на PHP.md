## Практическая работа № 2.2 Контроллер и представление на PHP.


**Цель:** Оптимизация разработки при помощи архитектурных паттернов разработки

**Контроллер** — связующее звено, соединяющее модели, виды и другие компоненты в рабочее приложение. Контроллер отвечает за обработку запросов пользователя. Контроллер не должен содержать SQL-запросов. Их лучше держать в моделях. Контроллер не должен содержать HTML и другой разметки. Её стоит выносить в виды.

**Вид(view)** — используется для задания внешнего отображения данных, полученных из контроллера и модели. Виды cодержат HTML-разметку и небольшие вставки PHP-кода для обхода, форматирования и отображения данных. Не должны напрямую обращаться к базе данных. Этим должны заниматься модели. Не должны работать с данными, полученными из запроса пользователя. Эту задачу должен выполнять контроллер.

Из теории мы знаем, что вывод html и обращения к базам данных из контроллера это ошибка логики MVC(с данными должна работать модель, а не контроллер он связующее звено). Пока что мы оставим это чтобы просто протестировать работу контроллера(будто бы он уже получил данные от модели), а уже после реализации модели и представления сделаем правильно.

2. Задание 2

#### Реализуем класс View.php:

```php
<?php 

namespace App\Core; 

class View 

{ 

    public static function render(string $template, array $data = []): void 

    { 

        extract($data); // $articles / $article станут переменными 

        $viewFile = __DIR__ . '/../Views/' . $template . '.php'; 

        if (!file_exists($viewFile)) { 

            http_response_code(500); 

            exit("View not found: {$template}"); 

        } 

        ob_start(); 

        require $viewFile; 

        $content = ob_get_clean();  // содержимое шаблона 

        require __DIR__ . '/../Views/layout.php'; // обёртка 

    } 

}
```
Проясним что делает этот наш чудо класс. У нас дальше будут шаблоны представления данных, (template), и мы их будем рендерить. 


Если посмотреть на метод render то он не проводит никакую обработку данных а просто выводит то что ему передали ($data), а что там внутри уже всё равно. А вот $template это важно он должен существовать, и любую дичь туда не впишешь. Метод проверяет существует ли указанный шаблон. Если не существует то отправляем ошибку. Если существует то идем дальше.


Дальше чёт какой то **ob_start()** идёт, что эта и зачем? А вот ща распишем.

Здесь когда мы получили шаблон представления данных, мы не хотим сразу отправлять его браузеру. ob_start это функция php которая сначала запишет вывод шаблона в буфер а уже потом мы сможем его отправить. Здесь мы его записали в переменную $content и с помощью метода ob_get_clean забрали данные из буфера. 

А зачем заниматься этой дичью? А вот зачем. Представим что у нас есть сайт с одинаковой шапкой, футером и т.п. и вписывать это в каждом файле неудобно. Мы создаем обёртку layout.php в которой прописываем все те блоки что не меняются, и уже потом выводим наши шаблоны внутри. 

Если еще проще. Представим что у нас был сайт с красным фоном и тут нам говорят, надо сделать зеленый фон. А у нас 500 шаблонов. Без layout мы будем менять шаблон во всех 500 файлах и плакать ибо на что мы тратим свою жизнь. С layout достаточно поменять фон только в одном файле.


#### Обновляем Controller.php:

```php
<?php 

namespace App\Core; 

abstract class Controller 

{ 

    protected function view(string $template, array $data = []): void 

    { 

        View::render($template, $data); 

    } 

}
```
Создаём общий метод для всех существующих и будущих контроллеров view.
Ну, просто потому что именно контроллер говорит что делать и управляет. View.php сам себя работать не заставит. А общий метод потому что он нужен всем контроллерам и тут логика та же, чтобы не писать в каждом контроллере дубликат метода сделаем его в Controller.php.

#### Создаем шаблон для вывода всех статьей(По сути шаблон для основной страницы index.php)

#### Обновим ArticleController.php:

```php
<?php 

namespace App\Controllers; 

use App\Core\Controller; 

class ArticleController extends Controller 

{ 

    public function index(): void 

    { 

        $articles = [ 

            ['id' => 1, 'title' => 'Первая статья', 'content' => '...'], 

            ['id' => 2, 'title' => 'Вторая статья', 'content' => '...'],

        $this->view('articles/index', ['articles' => $articles]);

    { 

        $article = [

}
```
