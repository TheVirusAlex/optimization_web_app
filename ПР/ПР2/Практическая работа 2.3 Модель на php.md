
## Практическая работа 2.3 Модель на php

Цель: Оптимизация разработки при помощи архитектурных паттернов разработки.

**Model** - Это основная логика приложения. Отвечает за данные, методы работы с ними и структуру программы. Модель реагирует на команды из контроллера и выдает информацию и/или изменяет свое состояние.


1. Задание 1
   
   
   #### Создаем БД
   
Базу данных можно создать с помощью интерфейса phpmyadmin или через php:
   
   ```php
CREATE DATABASE mvc_demo CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci; 

USE mvc_demo; 

CREATE TABLE articles ( 

    id INT AUTO_INCREMENT PRIMARY KEY, 

    title VARCHAR(255) NOT NULL, 

    content TEXT NOT NULL, 

    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP 

);
   ```

#### Создадим файл db.php

```php
<?php 

return [ 

    'host'     => 'your_host', 

    'dbname'   => 'mvc_demo', 

    'user'     => 'user_name', 

    'password' => 'user_password', 

    'charset'  => 'utf8mb4', 

];
```

Здесь мы записываем данные для подключения к базе данных, чтобы не писать их каждый раз. Тут снова та же логика, в случае изменения данных подключения нужно редактировать лишь 1 файл.

#### Создаем DataBase.php

```php
<?php 

namespace App\Core; 

use PDO; 

class Database 

{ 

    private static ?PDO $pdo = null; 

    public static function pdo(): PDO 

    { 

        if (self::$pdo === null) { 

            $config = require __DIR__ . '/../../config/db.php'; 

            $dsn = "mysql:host={$config['host']};dbname={$config['dbname']};charset={$config['charset']}"; 

            self::$pdo = new PDO($dsn, $config['user'], $config['password'], [ 

                PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION, 

                PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC, 

            ]); 

        } 

        return self::$pdo; 

    } 

}
```
Реализуем подключение к базе данных. Одно подключение на всё приложение.



#### Создаем модель Article.php:

```php
<?php 

namespace App\Models; 

use App\Core\Database; 

class Article 

{ 

    public function all(): array 

    { 

        return Database::pdo() 

            ->query("SELECT * FROM articles ORDER BY created_at DESC") 

            ->fetchAll(); 

    } 

    public function find(int $id): ?array 

    { 

        $stmt = Database::pdo()->prepare("SELECT * FROM articles WHERE id = ?"); 

        $stmt->execute([$id]); 

        return $stmt->fetch() ?: null; 

    } 

}
```

Задача модели в данном случае проста, просто получить данные и отдать их. Очень простая реализация. Метод all отдает все статьи, метод find ищет конкретную.

#### Обновляем ArticleController.php:

```php
<?php 

namespace App\Controllers; 

use App\Core\Controller; 

use App\Models\Article; 

class ArticleController extends Controller 

{ 

    private Article $model; 

    public function __construct() 

    { 

        $this->model = new Article(); 

    } 

    public function index(): void 

    { 

        $this->view('articles/index', [ 

            'articles' => $this->model->all(), 

        ]); 

    } 

    public function show(int $id): void 

    { 

        $article = $this->model->find($id); 

        if (!$article) { 

            http_response_code(404); 

            exit('Статья не найдена'); 

        } 

        $this->view('articles/show', ['article' => $article]); 

    } 

}
```

Итоговый вывод: В ходе этой работы мы реализовали модель и завершили наш MVC.
Наконец всё работает так как задумано, Роутер направляет запрос в Контроллер, он запрашивает данные из модели, модель обращается к базе данных и отдает их контроллеру, контроллер отправляет данные в представление и оно их рендерит. 
В процессе работы мы увидели полезность MVC и роутера. Роутер освободил от ручной маршрутизации, а архитектура MVC разделила задачи на 3 части, что сделает проще будущее масштабирование, обновление приложения и читаемость кода.
